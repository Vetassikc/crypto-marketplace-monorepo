# Marketplace V2 Technical Audit

Date: February 18, 2026  
Scope: Repository-level audit of architecture, implementation readiness, subprocesses, and delivery process.

## 1. Overall Maturity Snapshot
- Product concept and UX direction: **Strong**
- Core marketplace CRUD baseline: **Implemented**
- Web3 escrow foundation: **Partially implemented**
- Fiat payments: **Not implemented**
- AI features: **Partially implemented**
- Security posture: **Needs hardening**
- Testing and CI maturity: **Low**
- Documentation consistency: **Medium (improving)**

## 2. Critical Findings (Priority Ordered)

### P0 (Immediate)
1. Hardcoded API secret existed in web API route (`apps/web/app/api/generate-description/route.ts`).  
Status: fixed in this audit pass (moved to env-based config).

2. Backend CORS was open to any origin in `apps/api/src/main.ts`.  
Status: fixed to env-driven allowlist baseline (`CORS_ORIGIN`).

3. Wallet login flow has no SIWE signature verification; address-only login in `apps/api/src/users/users.service.ts`.  
Risk: account spoofing.

### P1 (Short-term)
1. Order creation paths still include hardcoded buyer assumptions in frontend pages.
2. No robust backend authorization guards for listing/order ownership actions.
3. LLM output from smart search is parsed without strict schema validation.
4. `apps/docs` remains mostly template content and does not reflect platform docs.

### P2 (Medium-term)
1. Root automation lacks CI workflow (`.github/workflows` missing).
2. Incomplete test strategy (no consistent `test` task across workspaces).
3. Build warning debt remains (wagmi optional connector dependency warnings during webpack build).

## 3. Subprocess Health

### 3.1 Seller Onboarding
- Wallet connect works.
- User record auto-creation works.
- Missing: verified identity flow, role upgrade workflow, policy checks.

### 3.2 Listing Publication
- Works end-to-end in MVP form.
- Missing: policy moderation, anti-spam controls, strong ownership checks.

### 3.3 Buyer Checkout (Crypto)
- UI contract interaction exists.
- Missing: backend reconciliation guarantees, deterministic order state machine, dispute lifecycle APIs.

### 3.4 Buyer Checkout (Fiat)
- Not started.
- Required for product promise: hybrid fiat + crypto marketplace.

### 3.5 AI Assistance
- Smart search and AI listing text generation exist.
- Missing: AI accountant domain, data pipeline, and accounting-grade output contracts.

## 4. Recommended Execution Sequence
1. Security baseline sprint (SIWE, authz guards, CORS allowlist, rate limits).
2. Checkout architecture sprint (split fiat/crypto orchestration, order state machine).
3. AI accountant discovery + schema sprint (ledgers, categories, tax/report outputs).
4. Quality gates sprint (CI, tests, release checklist).
5. Scale sprint (observability, performance budgets, retries/idempotency).

## 5. Exit Criteria for “Agent-Ready” Development
- Stable planning artifacts in root (`task.md`, `implementation_plan.md`, `walkthrough.md`)
- Every sprint has measurable acceptance criteria
- Mandatory quality gate before merge: lint + typecheck + tests
- Documentation update required for every architecture-impacting change
- Security checklist attached to every checkout/auth change
